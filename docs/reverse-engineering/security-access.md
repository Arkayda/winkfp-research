# Security Access & Authentication Orchestration

This document details the reverse-engineered control flow of the primary authentication orchestrator `FUN_0041c920` in `winkfpt.exe`.

---

## 1. Sequence Flow of `FUN_0041c920`

```text
       WinKFP (FUN_0041c920)                             Target ECU
                 │                                           │
                 │ 1. job SERIENNUMMER_LESEN                 │
                 ├──────────────────────────────────────────>│
                 │ <─────────────────────────────────────────┤ (Returns Serial[4])
                 │                                           │
                 │ 2. Read HDD_AUTHENTISIERUNGS_LEVEL        │
                 │    Configure timers (10000ms, 0x1E46ms)   │
                 │                                           │
                 │ 3. job NG_AUTHENTISIERUNG_START           │
                 ├──────────────────────────────────────────>│
                 │ <─────────────────────────────────────────┤ (Returns Seed[8] & Mode)
                 │                                           │
                 │ 4. Compute Auth Token via KrApi           │
                 │    (GetAuthKey -> 3DES -> Hash/RSA)       │
                 │                                           │
                 │ 5. job NG_AUTHENTISIERUNG_START           │
                 │    payload: {1, level, 0, Token..., 3}    │
                 ├──────────────────────────────────────────>│
                 │ <─────────────────────────────────────────┤
                 │                                           │
                 │ 6. Evaluate JOB_STATUS / Status Code      │
                 │    - "OKAY" -> Proceed to Flash           │
                 │    - "ROUTINE_NOT_COMPLETE" -> Retry      │
                 │    - "ERROR_AUTHENTICATION" -> Abort      │
```

## 2. Step-by-Step Execution Details

### Step 1: Serial Number Acquisition
* WinKFP dispatches EDIABAS job `SERIENNUMMER_LESEN`.
* Result set `SERIENNUMMER` provides the 4-byte serial number of the target ECU (used as salt in symmetric and asymmetric hash derivations).

### Step 2: Level & Timer Initialization
* Reads internal parameter `HDD_AUTHENTISIERUNGS_LEVEL` (typically `1`).
* Initializes security timeout timers:
  * Base timeout: `10,000 ms`.
  * Secondary timer: `0x1E46 ms` (7,750 ms).
  * Dynamic attempt timer: `(N + 1) * 1,000 ms`, where $N$ is the current retry iteration.

### Step 3: Seed & Mode Negotiation
* Dispatches job `NG_AUTHENTISIERUNG_START` without parameters.
* Reads two key result strings:
  1. `ZUFALLSZAHL`: 8-byte random seed generated by the ECU flash bootloader.
  2. `AUTHENTISIERUNG`: String indicating the required cryptographic mode (`"Symetrisch"`, `"Simple"`, or `"Asymetrisch"`).

### Step 4: Token Computation
* Calls `GetAuthKey` (`FUN_004b8fe0`) to fetch the key container and decrypt the target ECU's key.
* Passes seed, serial, and generated nonce into `KrApiAuthenticate` (`FUN_004b95a0`).

### Step 5: Token Submission
* Dispatches `NG_AUTHENTISIERUNG_START` with binary payload formatted as:
  ```text
  [0]     0x01 (Sub-function / send key)
  [1]     Security Level (from HDD_AUTHENTISIERUNGS_LEVEL, typically 0x01)
  [2]     0x00
  [3..N]  Computed Authentication Token bytes
  [N+1]   0x03 (ETX terminator)
  ```

## 3. Status Handling & Retry Semantics

WinKFP inspects the returned `JOB_STATUS` and ECU error codes:

| Returned Status | Description | WinKFP Behavior |
|---|---|---|
| `"OKAY"` | Security Access Granted. | Transitions to VDLE download phase. |
| `"ROUTINE_NOT_COMPLETE"` | ECU crypto coprocessor still verifying or busy. | Waits, acquires fresh seed, and increments retry counter. |
| `"ERROR_AUTHENTICATION"` | Invalid key / rejected token. | Immediate failure; logs error token and aborts. |
| `"NO_RESPONSE"` | Diagnostic timeout. | Checks bus voltage and attempts re-synchronization. |

### Retry Chain Rules
* Maximum retry count: **3 attempts**.
* On each retry, WinKFP **must obtain a fresh seed** (`AUTHENTISIERUNG_ZUFALLSZAHL_LESEN`). Replaying an old token against a new seed is immediately rejected by the ECU.
* The internal log records the outgoing key token under the label `SG-Schluessel`.
