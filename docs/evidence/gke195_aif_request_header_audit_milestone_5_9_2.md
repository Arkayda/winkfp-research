## 1. Executive Summary & Audit Objective

A follow-up consistency audit was initiated on the canonical request headers for `AIF_LESEN` across the Milestone 5.9 documentation and the Milestone 5.9.1 checksum audit table.

### The Inconsistency
- In Milestone 5.9 canonical job table:
  `AIF_LESEN` request was documented as starting with byte `0x86`:
  `86 18 F1 23 ... <CS>`
- In Milestone 5.9.1 checksum audit table:
  `AIF_LESEN` row documented the format byte as `0x81` (derived from previous minimal `request_payload=b"\x23"`).

Under the established BMW-FAST / DS2 framing rules:
$$\text{Format Byte} = 0x80 \mid \text{len}(\text{payload})$$
A frame starting with `0x86` requires exactly 6 bytes of payload ($0x86 \ \& \ 0x3F = 6$). A frame with 1 byte of payload (`b"\x23"`) produces format byte `0x81`. The documented format byte, the actual first byte of the documented request, and the Request Builder output must strictly coincide.

## 2. Authoritative OEM Sources of Truth

### 2.1 SGBD Bytecode: `10FLASH.prg`
Inspection of decoded `10FLASH.prg` binary driver confirms three independent telegram definitions for `AIF_LESEN` (at bytecode offsets `0x029E39`, `0x02F04B`, and `0x02FA90`):
```text
Opcode 0x1D (LOAD_TELEGRAM): length = 9 bytes
Telegram template: 86 FF F1 23 00 00 00 07 00
```
- Byte 0: `0x86` (Format byte: short frame with 6 bytes of payload)
- Byte 1: `0xFF` (Target ECU address placeholder, substituted by target at runtime)
- Byte 2: `0xF1` (Tester address)
- Bytes 3–8: `23 00 00 00 07 00` (6 bytes of payload: Service 0x23, 4-byte address, 1-byte length placeholder)

### 2.2 Historical Factory Session Trace: `traces/sanitized/sanitized_flash_session.trc`
Line 11956–11961 records the exact request buffer executed by EDIABAS for `AIF_LESEN` on target `10FLASH`:
```text
_TEL_AUFTRAG = 9 Bytes:
    000: 86 78 F1 23 00 00 00 07
    008: 12
```
- Length: Exactly 9 bytes in EDIABAS telegram buffer.
- Format byte: `0x86`.
- Target: `0x78` (factory module `10FLASH`).
- Tester: `0xF1`.
- Payload (6 bytes): `23 00 00 00 07 12` (Service 0x23, Address `00 00 00 07`, Length `0x12` = 18 bytes decimal, corresponding to `AIF_GROESSE = +18`).

### 2.3 Diagnostic Protocol Rule (KWP2000 / ISO 14230)
KWP2000 Service `$23` (`ReadMemoryByAddress`) strictly requires memory address and memory size parameters. A bare 1-byte request (`0x23`) is invalid diagnostic protocol and would be rejected with NRC 0x13 (`IncorrectMessageLengthOrInvalidFormat`). The 6-byte payload `23 00 00 00 07 12` is the canonical telegram for `AIF_LESEN`.

- Payload: `23 00 00 00 07 12` (6 bytes)
